1. The problem: agreeing on a secret in public

Every time you see the padlock in your browser, two computers that have never met have just agreed on a secret code — while anyone on the network could be listening to every message they sent each other. That sounds impossible. How do you whisper across a crowded room?

The answer is a special kind of math operation: one that is easy to do but hopeless to undo. Think of mixing paint. Mixing blue into yellow is easy; un-mixing the green back into its two ingredients is not. If you have a mathematical version of paint-mixing, strangers can build a shared secret out in the open, and eavesdroppers are left holding a bucket of green.

Elliptic curve cryptography (ECC) is one such operation. This page builds it up from scratch: first a curve, then a strange rule for "adding" points on it, then a twist that turns that rule into a one-way street. Every picture below is live — drag things and see what happens.

2. Meet the curve

Despite the name, an elliptic curve is not an ellipse. It is the set of points (x, y) that satisfy

y² = x³ + a·x + b

for some chosen numbers a and b. Move the sliders to change them. Sometimes the curve is a single sweep, sometimes it pinches off into an "egg" plus a tail.

One thing to notice, because it matters later: the curve is always a mirror image across the horizontal axis. If (x, y) is on the curve, so is (x, −y), because squaring a negative number gives the same result.

3. Adding points (the weird rule)

Here is where it gets interesting. We are going to define a way to "add" two points on the curve and get a third point on the curve. The rule is geometric:

  1. Draw a straight line through P and Q.
  2. That line hits the curve at exactly one more spot. Call it R.
  3. Flip R across the horizontal axis. That mirror point is P + Q.

Drag P and Q anywhere along the curve.

Why the flip? Without it, the rule would not behave like addition. With it, everything works the way you'd hope: P + Q = Q + P, you can group additions however you like, and there is even a "zero".

What if the line is vertical? Drag Q to be the mirror image of P. The line shoots straight up and never comes back to the curve. We say it hits the point at infinity, and we call that point O. It behaves exactly like zero: P + O = P, and a point plus its mirror image is O.

What if P and Q are the same point? Tick the checkbox. There is no longer a unique line through "two" points, so we use the tangent line — the line that just grazes the curve at P. The result is P + P, which we write as 2P.

4. Hopping: P, 2P, 3P, 4P, …

Once you can add, you can add repeatedly. Start at P, add P to get 2P, add P again to get 3P, and so on. Each hop is the same line-and-flip trick. We write k·P for "P added to itself k times".

Drag P to a new start. Use the slider to hop.

Here is the question the whole subject turns on. Suppose I show you P and I show you the point I landed on after some number of hops. Can you tell me how many hops I took? On this smooth curve you might manage it by tracing the bounces. The next section makes that impossible.

5. Make it a clock

On a 12-hour clock, 10 + 5 is not 15 — it's 3. Numbers wrap around. Mathematicians call this arithmetic modulo 12, and you can do it with any modulus; cryptography uses a prime number, which we'll call p.

Now the twist: take the same curve equation, but only allow whole-number coordinates from 0 to p − 1, and check the equation on a clock of size p. The smooth curve shatters into a cloud of dots.

It looks like static, but it isn't random. Look for the mirror symmetry across the middle: the top half reflects the bottom half, just like the smooth curve, because −y on a clock is p − y.

Better still, the addition rule still works. There is no visible line any more, but the formula behind "draw a line, find the third point, flip" only uses adding, multiplying and dividing, and all of those work on a clock. So tap a dot to pick a starting point G, then hop.

Tap a dot to choose G.

Watch where the hops land: 2G, 3G, 4G… leap all over the grid with no pattern you could eyeball. And eventually the sequence lands on O (the zero) and starts over — the number of hops that takes is called the order of G. That's the whole toolbox. Time to build a lock.

6. The one-way trick

From here on we'll fix the curve to y² = x³ + 7 over p = 97, with starting point G = (1, 28). (That's a toy cousin of the curve Bitcoin uses, which has the very same x³ + 7 but a 78-digit prime.) It has 79 points, and hopping from G visits every single one of them before wrapping back to O.

The computer has picked a secret number k and hopped that many times from G. It shows you where it landed: Q = k·G. Your job: figure out k. Move the slider to try candidates.

You found it, but only by trying values until one matched. There was no shortcut. With 79 points, that's fine; a computer would be done in a microsecond. Now scale it up.

Bitcoin's curve has this many points:

115 792 089 237 316 195 423 570 985 008 687 907 852 837 564 279 074 904 382 605 163 141 518 161 494 337

That's about 1077. The best known shortcut for this guessing game still needs roughly the square root of that many steps — around 1038. If every computer on Earth worked on it, the sun would burn out first.

But going forwards is cheap. To compute k·G you don't hop k times. You double: G, 2G, 4G, 8G… and add together the ones you need, following the binary digits of k. Your current guess would take . A 78-digit k takes about 400 hops. Trivial.

That asymmetry — hopping forward is easy, counting hops backward is impossible — is the paint-mixing trick. It's called the elliptic curve discrete logarithm problem, and everything else is built on it.

7. Two strangers agree on a secret

Alice and Bob want a shared secret. Eve is reading every message. Here's the protocol (it's called Elliptic Curve Diffie–Hellman, or ECDH):

  1. Everyone agrees, in public, on the curve and the start point G.
  2. Alice picks a secret number a and sends Bob A = a·G. Bob picks a secret b and sends Alice B = b·G.
  3. Alice computes a·B. Bob computes b·A.

Both of those are a·b·G — the same point. Eve saw G, A and B go by, but to get the shared point she'd need a or b, and that means solving the hop-counting problem from the last section.

Change either secret and the shared point moves — but it always moves for both of them together. That shared point is then fed into an ordinary cipher to encrypt the actual conversation. This is, more or less exactly, what happens in the first few milliseconds of every secure web connection.

8. In the real world

  • HTTPS. The padlock. Your browser and the server do ECDH on a curve named P-256 or Curve25519 before any page loads.
  • Messaging. Signal and WhatsApp use Curve25519 to set up keys for end-to-end encryption.
  • Bitcoin and Ethereum. Your "private key" is a number k; your public key is k·G on the curve secp256k1, which is y² = x³ + 7 over a 256-bit prime. Signing a transaction proves you know k without revealing it.
  • Passkeys, SSH keys, secure boot. Same trick, different wrapping.

Why curves rather than the older RSA system? Size. A 256-bit elliptic curve key is about as strong as a 3072-bit RSA key, so it's smaller, faster, and easier on phones and smart cards.

What we skipped

Plenty. Digital signatures (ECDSA, EdDSA) build on the same hop-counting problem. Choosing a curve is delicate: some curves have hidden shortcuts and are avoided. Real implementations must run in constant time so a spy can't measure how long the hops took. And a large quantum computer, if one is ever built, could count hops efficiently — which is why the field is quietly moving to "post-quantum" schemes. But the core idea you've now seen — easy to hop forward, impossible to count backward — is the heart of it.
